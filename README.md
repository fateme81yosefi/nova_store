# NOVA Store

ویترین فروشگاه NOVA. با Next.js نوشته شده و محصول را از [FakeStoreAPI](https://fakestoreapi.com) می‌خواند. پنل مدیریت مخزن جداگانه‌ای است.

## پیش‌نیاز

Node 20 یا جدیدتر.

## نصب و اجرا

```bash
npm install
cp .env.example .env
npm run dev
```

روی `http://localhost:3000` بالا می‌آید. پیشوند زبان همیشه هست و پیش‌فرض فارسی است، پس خانه `/fa` است و انگلیسی `/en`.

## بیلد

```bash
npm run build
npm start
```

## متغیرها

هر سه تا در `.env.example` هستند. پیشوند `NEXT_PUBLIC_` یعنی مقدار داخل باندل کلاینت هم هست. رمز و توکن بینشان نیست.

- `NEXT_PUBLIC_API_BASE_URL` آدرس FakeStoreAPI است.
- `NEXT_PUBLIC_SITE_URL` پایهٔ متادیتا، `sitemap` و `robots` است. برای لوکال همان `http://localhost:3000` می‌ماند.
- `NEXT_PUBLIC_USD_TO_TOMAN` فقط پشتیبان است. سرور اول نرخ بازار آزاد دلار را از [نرخ‌آرا](https://nerkhara.com/api/v1/latest/usd.json) می‌گیرد. اگر آن درخواست خطا بدهد، نرخ کهنه باشد، یا واحدش تومان نباشد، این مقدار استفاده می‌شود. اگر خود متغیر هم خالی یا نامعتبر باشد، هر دلار ۵۰ هزار تومان حساب می‌شود.

نتیجهٔ نرخ‌آرا ۱۰ دقیقه کش می‌شود. نرخ روی خود صفحه نوشته شده و اگر زنده باشد لینک منبع هم کنارش هست.

## معماری

App Router است. صفحهٔ خانه، جزئیات محصول و چیدمان زبان کامپوننت سرور هستند و داده را همان‌جا می‌گیرند. کاتالوگ، سبد و هدر کلاینت‌اند، چون جستجو، تعداد سبد و تم با کاربر عوض می‌شوند.

مسیرها:

- `/[locale]` فهرست محصول
- `/[locale]/products/[id]` جزئیات، با `generateMetadata`
- `/[locale]/cart` سبد. این یکی ایندکس نمی‌شود
- `sitemap.ts` خانه و صفحهٔ هر محصول را برای هر دو زبان می‌سازد
- `robots.ts` به همان sitemap اشاره می‌کند

زبان با next-intl است. متن‌ها در `dictionary` هستند و داخل JSX جملهٔ ثابت ننوشتم. `proxy.ts` درخواست را به زبان درست می‌فرستد. در Next 16 این فایل جای middleware را گرفته.

`dir` صفحه از روی زبان است: فارسی راست‌به‌چپ، انگلیسی چپ‌به‌راست.

## چی کجاست

- `app` مسیرها، متادیتا، صفحهٔ خطا، sitemap و robots.
- `components` کاتالوگ، جزئیات محصول، سبد و خبرنامه.
- `shared` هدر، فوتر، قیمت و جعبهٔ جستجو.
- `requests` خواندن محصول و نرخ دلار.
- `api` نمونهٔ Axios. فهرست محصول را با `fetch` می‌خوانم تا کش خود Next روشنش باشد.
- `storage` سبد با Zustand و تم با localStorage.
- `context` تم و نرخ دلاری که از سرور به کلاینت می‌رسد.
- `dictionary` متن فارسی و انگلیسی.
- `i18n` زبان‌ها، لینک داخلی و canonical هر صفحه.
- `utils` فیلتر کاتالوگ و قالب تومان.
- `validations` اسکیمای ایمیل خبرنامه.
- `modals` منوی موبایل.
- `styles` رنگ روشن و تیره.
- `types` نوع محصول و سبد، و enumها.
- `assets` فونت وزیرمتن و آیکون‌ها.

جستجو، دسته، مرتب‌سازی و شمارهٔ صفحه توی query string هستند. خبرنامه فقط `useState` محلی دارد تا پیام موفقیت را نشان بدهد و جایی ارسال نمی‌شود.

## وضعیت

سبد بین نشان هدر، کارت محصول و صفحهٔ سبد مشترک است و فقط مال همین مرورگر است. محصول را سرور می‌آورد، پس برایش استور نساختم. Zustand با `persist` همان سبد را در localStorage نگه می‌دارد و Provider نمی‌خواهد. کلیدش `nova-cart` است.

`skipHydration` روشن است. HTML سرور سبد را خالی می‌بیند، چون به localStorage دسترسی ندارد. اگر کلاینت همان لحظهٔ اول سبد ذخیره‌شده را بخواند، دو HTML با هم فرق دارند و هیدریشن به‌هم می‌ریزد. با این فلگ خواندن عقب می‌افتد. بعد از mount، در `ThemeProvider` این را صدا می‌زنم:

```ts
useCart.persist.rehydrate()
```

صفحهٔ سبد تا تمام شدن همین هیدریشن فهرست را نشان نمی‌دهد، تا یک لحظه خالی چشمک نزند.

تم جدا از سبد است. اول روشن است و بعد از mount از localStorage خوانده می‌شود. روی تگ `html` مقدار `suppressHydrationWarning` هست، چون `data-theme` را کلاینت عوض می‌کند.

## SSR

چیدمان زبان، خانه، صفحهٔ محصول و sitemap مقدار `revalidate` را ۶۰ ثانیه گذاشته‌اند. خود `fetch` محصول هم `next.revalidate` شصت‌ثانیه‌ای دارد. `cache()` از React درخواست تکراری داخل یک رندر را یکی می‌کند.

`generateStaticParams` شناسهٔ محصول‌ها را برای ساخت صفحه می‌گیرد. اگر موقع بیلد API در دسترس نباشد، لیست خالی برمی‌گردد و صفحه با اولین درخواست ساخته می‌شود.

هر صفحه canonical و alternate زبان مقابل را دارد. عنوان و توضیح صفحهٔ محصول از خود کالا می‌آید.

استایل با styled-components است. کامپایلر Next روشن است و `StyledRegistry` استایل رندر سرور را داخل HTML می‌گذارد تا صفحه اول بدون استایل نیاید.

اگر گرفتن محصول روی سرور خطا بدهد، خانه همان وضعیت را به کاتالوگ می‌دهد و مرورگر یک بار دیگر درخواست می‌کند.

## API

آدرس از `NEXT_PUBLIC_API_BASE_URL` خوانده می‌شود. سه خواندن داریم: `/products`، `/products/categories` و `/products/:id`. اگر دسته نیاید، دسته را از روی خود محصول‌ها می‌سازم.

قیمت API دلار است. تومان همان نرخ بازار آزاد است، یا در نبودش نرخ پشتیبان. فرم خریدی که دلار بفرستد اینجا نیست. فروشگاه فقط نشان می‌دهد.

Axios روی پاسخ ۴۰۱ یک listener دارد. فروشگاه ورود ندارد، پس کسی آن listener را ثبت نکرده و ۴۰۱ صفحه را بیرون نمی‌اندازد.

## محدودیت‌های FakeStoreAPI

API چیزی را ذخیره نمی‌کند. سبد فقط در localStorage همین مرورگر می‌ماند. خبرنامه به جایی نمی‌رود و پرداخت ندارد.

ویترین فقط می‌خواند. ساخت و ویرایش محصول و کاربر مال پنل است.

صفحه‌بندی و جستجوی سمت سرور ندارد. فیلتر، مرتب‌سازی و صفحه‌بندی روی همان لیست کلاینت است و هر صفحه ۸ محصول است.

شناسه و دادهٔ محصول ثابت‌اند. با رفرش، چیزی که در پنل ساخته شده اینجا دیده نمی‌شود.

گاهی درخواست سرور به API از پشت Cloudflare با ۴۰۳ برمی‌گردد، در حالی که همان آدرس در مرورگر باز می‌شود. در آن حالت خانه خطا را نشان می‌دهد و از کلاینت دوباره تلاش می‌کند. sitemap اگر محصول نگیرد فقط دو آدرس خانه را برمی‌گرداند.
